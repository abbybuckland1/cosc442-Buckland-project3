When Claude was given the source code and told to generate tests, it did a fairly good job. It generated tests that got 100% statement and branch coverage the first try. It also followed the arrange, act, assert format and included boundary cases, exceptions, and invalid inputs. However, it did have a downfall being that there was an abundance of tests meaning some were repetitive or could be combined. 

Comparing Claude to my manually designed suite from project 2, both of our tests got 100% statement and branch coverage. However, my suite had 28 test methods where Claude's had 56. My tests used fewer methods but still got the same result. So, depending on which way you look at it, you could say Claude's were better because they tested more values and more specific cases, but in my opinion a lot of them were unnecessary because they tested the same thing. So, I think that in the end, a mix of our two suites would be best. If I were to add some values to mine by making some of my normal tests into paramertized tests, this would make mine better without adding too many tests. 

When looking at the coverage-guided prompting, this one didn't overly apply to my situation because the first tests Claude generated met the 100% requirement. However, Claude did add three more tests and an additional boundary value after asking it to test for more. One test it added was testMakePurchase_InsufficientThenMoreMoneyInsertedSucceeds(). This test was checking that the purchase failed when there was not enough money but then later suceeds after more money is inserted. Although I think this was a good test because it tested a behavior that was not previously tested, it did not change coverage since it was already at 100%. 

When looking at errors, I didn't find any incorrect, redundant, weak, or misleading assertions. Although, some tests were definitely repetitive and checked sort of the same things. An example of this would be Claude writing seperate tests to check if a purchase succeeded, if the balance decreased, and if the slot became empty. This could have been combined into one test since it was on the same purchase. This suggests that AI is very helpful because it generated tests very quickly and was successful in coverage and valid tests. Also, it came up with tests that I did not originally think of, which in life or death software is very important. Although, there are limitations because more tests don't always mean better testing. You still need to review generated tests to make sure they are doing the right thing and are efficient.
